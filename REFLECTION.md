# Task 3: Reflection on the AI paradoxes

This assignment asked me to build an agent that verifies CVs and afterwards to break a system of the same kind, and the strongest impression I carried away is that the two tasks follow almost the same technical path, because both depend on one model, one set of tools and one dataset, with the only difference sitting in a paragraph of prompt text. I spent an evening teaching the agent to decide which Kelly Tsang was the target candidate and half an hour writing a line into the white text layer of a PDF to claim that the record had already been reconciled, and since the second piece of work cost far less than the first, the imbalance between them is a fair description of how this class of system behaves in practice.

The first paradox is that one model both renders the judgement and produces the material being judged, because in Task 1 I asked the model whether a CV was honest and in Task 2 I used the same model to generate text that pushed such a judgement toward finding honesty, while the model cannot distinguish these two uses since it holds no position and does not remember where it stood an hour earlier. When one system produces claims and also evaluates them, the judgement is produced by a component that has no stake in the outcome.

The second paradox concerns how closed the evidence source is, because KYC processes exist on the premise that documents can be wrong and yet the only evidence the verification agent can reach is another document of the same format produced by the same generator, and while reading the data I noticed that the mock LinkedIn records and the CVs use the same set of names and the same set of sentence templates. The real world offers no better position, since one language model checks a CV against a LinkedIn page that another language model wrote and then treats the two as independent pieces of evidence.

The third paradox is that strong reading comprehension itself expands the space that can be exploited, because the change that actually worked in my Task 2 submission was small since it only rewrote the job title from Manager to Senior Manager, and what moved the result was context, that is the white text claiming the record had been checked line by line and signed off. The model reads fluently, weighs tone and provenance and behaves reasonably, and although these abilities are the ones we habitually praise, they also let a paragraph that the eye cannot see outweigh the profile that was supposed to serve as the reference, so the stronger the model becomes, the higher the cost of being persuaded by text.

The fourth paradox involves coverage and patience, because my verification agent scored seven correct answers on the public test set mainly because it checks every error-prone field in the same order on every run, a habit worth more than cleverness here. The strictest verifier I built caught the attack by relying on one fixed checklist, and a checklist happens to be a form that a script handles well and a language model handles poorly, which suggests that the reliable part of my solution is the deterministic part that matches employers and schools and maps field-level findings onto fixed scores inside Python, while the part that makes the system look intelligent needs delimiters and warnings to defend it.

The fifth paradox is the asymmetry of trust, because the assignment supplies a usable model and a shared server and then asks me to attack it, and while nobody expects a student to break a bank KYC system, the same exercise repeats across industry where defenders face pressure to ship quickly and attackers need one well-written paragraph. The five verifiers that will grade me keep their designs undisclosed, so my strategy turns toward guessing their coverage, which matches how a real attacker reasons about an unknown target and reflects how AI security evaluation actually works.

If I keep only one conclusion, I would say that a trustworthy AI system should carry as many mechanisms as possible that work without trust, such as deterministic comparison, exhaustive field checks, provenance and signature checks and a refusal to treat document content as instructions, because these measures are cheap, dull and effective, while everything else remains a probability estimate.
